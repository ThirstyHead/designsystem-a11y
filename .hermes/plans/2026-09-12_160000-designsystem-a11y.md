# Plan: designsystem-a11y Design System

## Goal
Create a machine-readable, WCAG-compliant design system based on the Design Tokens Specification (2025.10) to optimize agentic AI workflows and provide a "state of the art" accessibility baseline.

## Target
- Repository: `/Users/scott/code/local/designsystem-a11y`
- URL: `https://thirstyhead.com/designsystem-a11y`

## Core Principles
- **AI-First**: The system is designed to be consumed by LLMs and agents. `tokens.json` is the source of truth.
- **Accessibility-First**: Every token is validated against WCAG 2.1 AA/AAA contrast and usability standards.
- **Lean & Standards-Based**: Framework-free implementation using native CSS variables and HTML.

## Architecture
- **Token Store**: `tokens.json` following DTS 2025.10.
- **Implementation**: A documentation site that renders these tokens visually.
- **AI Interface**: `llms.txt` providing a high-level map and technical specifications for agents.

## Step-by-Step Tasks

### Phase 1: Token Definition & Specification
1. **Initialize Repository Structure**
   - Create `docs/css/`, `docs/js/`, `docs/assets/`.
   - Create `tokens.json` (Initial draft based on Japandi palette).
2. **Define Token Categories**
   - `color`: Primary, Secondary, Background, Surface, Text, Error, Success.
   - `typography`: Scale, Weights, Line-heights.
   - `spacing`: Base unit and scale.
   - `border-radius`: Standard curves.
3. **WCAG Validation**
   - Run contrast checks on all color pairs.
   - Document the contrast ratios in the token metadata.

### Phase 2: Documentation Site Implementation
4. **Build the Token Gallery**
   - Create `index.html` (Overview).
   - Create `colors.html` (Visual grid of all color tokens with hex and contrast ratios).
   - Create `typography.html` (Type scale examples).
   - Create `spacing.html` (Visual spacing guide).
5. **Implement SMACSS Architecture**
   - Use the same lean approach as `docx-a11y` to ensure consistency.
6. **Create `llms.txt`**
   - Provide a concise summary of the design system.
   - Link to `tokens.json`.
   - Explain the naming convention (e.g., `--sys-color-*`).

### Phase 3: Integration & Deployment
7. **Cross-Project Linkage**
   - Ensure `docx-a11y` can reference these tokens (via CSS import or build step).
8. **GitHub Pages Deployment**
   - Deploy to `https://thirstyhead.com/designsystem-a11y`.
9. **Final A11y Audit**
   - Ensure the design system site itself is a model of accessibility (100/100 Lighthouse).

## Validation
- **Machine Readability**: `tokens.json` validates against DTS 2025.10.
- **Accessibility**: All color combinations meet WCAG 2.1 AA.
- **AI Utility**: `llms.txt` allows an agent to understand the system without browsing every page.
